**# 2. ANATOMI STANDAR KONTRAK HALAMAN (PAGE CONTRACT)**

Setiap halaman di Servio wajib memenuhi kontrak 8 parameter terperinci berikut:

\`\`\`text

1\. Route & File Path       : Alur URL dan lokasi file di dalam Next.js App Router.

2\. Authorized Roles        : Siapa yang berhak mengakses (Customer, Provider, Worker, Ops, CEO).

3\. Tampilan / Sections     : Seluruh komponen visual dan section data yang ditampilkan di layar.

4\. Input yang Dibutuhkan   : Form fields, filter query, koordinat GPS, foto/video, parameter.

5\. Aksi yang Tersedia      : Tombol interaksi user (Submit, Cancel, Bayar, Nego, Konfirmasi).

6\. Kapan Aksi Disabled     : Aturan bisnis penguncian (cth: tombol bayar disabled jika sudah kedaluwarsa).

7\. Penanganan 11 State     : Loading Skeleton, Empty, Error, Offline, Stale, Expired, dll.

8\. Handoff / Next Route    : Ke mana sistem mengarahkan user setelah aksi berhasil diselesaikan.

# 12C. FRONTEND BUSINESS-RULE GUARDRAILS

1. Frontend state reflects backend/domain state; it must not invent business status.
2. Policy-driven deadlines must be rendered from state; do not hardcode auto-completion, return window, quotation validity, payment expiry, or snooze duration.
3. Payment UI never marks a transaction PAID based only on a local click.
4. Completion UI never directly executes payout/refund.
5. Support UI never directly executes financial transactions unless an explicit finance permission/flow exists.
6. Tracking UI never fabricates live location or ETA.
7. Service tracking must adapt to Home/Mobile/Emergency/Workshop/Remote/Project context.
8. Product reservation UI appears conditionally for supported Booking Barang types; it is not required for every product order.
9. Inventory UI distinguishes on-hand, reserved, allocated, unavailable, and available.
10. Fulfillment UI must not be treated as shipment tracking.
11. Shipment delivered state does not automatically mean order completed.
12. Return received does not automatically mean refund completed.
13. Return inspection may produce partial acceptance and partial refund.
14. Replacement is not represented as a new customer purchase.
15. Imported history/asset information must be visibly marked unverified where applicable.
16. AI recommendations require user action/confirmation before transactional changes.
17. Sensitive data is rendered according to active role and resource scope.
18. Frontend route guards are UX protection; backend authorization remains the security boundary.
